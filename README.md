# MyDigitalBrain 🧠

基于 **PARA 方法** 构建的个人知识库（Obsidian Vault）。目标是把散落的想法、项目资料和长期知识统一收进一个可检索、可链接、可回溯的系统里，让笔记从「收集」走向「产出」。

---

## 目录结构

```
MyDigitalBrain/
├── 00-Inbox（收集箱）     # 任何临时想法、摘录都先丢这里
├── 01-Daily（日记）       # 每日记录，搭配「日记」核心插件使用
├── 02-Projects（项目）    # 所有正在进行的工作项目
├── 03-Areas（领域）       # 持续关注的领域，如「编程」「投资」
├── 04-Resources（资源）   # 读书笔记、课程笔记、文献整理
├── 05-Archive（归档）     # 已完成的项目或失效笔记
└── 06-Templates（模板）   # 存放所有笔记模板
```

### 各目录职责

| 目录 | 说明 | 判断标准 |
|------|------|----------|
| **00-Inbox** | 唯一的入口。来不及分类的灵感、剪藏、待读文章都先放这里 | 还没想好放哪 → 放这里 |
| **01-Daily** | 以日期为单位的流水记录：今天做了什么、想到了什么 | 按天发生的事 |
| **02-Projects** | 有明确目标和**截止时间**的短期工作 | 有完成态的吗？ |
| **03-Areas** | 需要长期维护、没有终点的责任领域（编程、投资、健康……） | 需要一直关注吗？ |
| **04-Resources** | 可复用的知识资产：书摘、课程笔记、文献、参考资料 | 未来会回来查阅吗？ |
| **05-Archive** | 已结束的项目、不再维护的笔记 | 还需要它出现在视野里吗？ |
| **06-Templates** | Templater / 模板插件使用的笔记骨架 | 用于新建笔记 |

> **Projects 与 Areas 的区别**：项目有终点（「上线个人博客」），领域没有终点（「网站开发」）。项目结束后归档，领域长期留存。

## 工作流

```
收集 → 整理 → 执行/沉淀 → 归档
```

1. **收集（Inbox）**
   任何想法、链接、摘录，先无脑扔进 `00-Inbox`，不打断当前工作。

2. **整理（每日 / 每周）**
   定期清空 Inbox：为每条内容补上属性（tags）、标题，然后移动到真正该去的地方。
   **Inbox 的价值在于清空，而不是囤积。**

3. **执行与沉淀**
   - 有明确产出 → `02-Projects`
   - 长期关注 → `03-Areas`
   - 值得复用的知识 → `04-Resources`

4. **归档**
   项目完成后整体移入 `05-Archive`；过时的资源同样归档，保持主目录干净。

## 笔记规范

### 文件命名

- 使用**名词短语**，能独立看懂：`梯度下降原理.md` 而不是 `笔记1.md`
- 避免在文件名中使用 `/ \ : * ? " < > |` 等特殊字符
- 目录名保留数字前缀，保证排序稳定

### 通用笔记模板

所有新笔记建议从 `06-Templates（模板）/通用笔记模板.md` 创建，包含：

```yaml
---
created: {{date}} {{time}}
updated: {{date}} {{time}}
tags: []
---
```

正文结构：核心摘要 → 主要内容 → 相关链接 → 行动项。

### 链接优先

- 能用 `[[双链]]` 关联的，就不要只写纯文本
- 笔记之间多建立连接，未来靠「反向链接」和「关系图谱」找回
- 有用的事实写进笔记，不依赖记忆

## 插件

Vault 已安装并启用以下社区插件：

| 插件 | 用途 |
|------|------|
| **Templater** | 支持 `{{date}}`、`{{title}}` 等变量的动态模板 |
| **QuickAdd** | 快速捕获内容、一键套用模板 |
| **Calendar** | 日历视图，配合「日记」插件跳转 |
| **Dataview** | 用查询语句聚合笔记（按标签、更新时间等） |
| **Obsidian Git** | 自动 / 手动提交并推送，实现版本管理 |

核心插件中启用了：日记、模板、属性、书签、反向链接、关系图谱、同步等。

## 版本管理与备份

本仓库使用 Git 管理，历史提交形如 `vault backup: 2026-11-07 11:19:51`。

- Obsidian 配置目录 `.obsidian/` 已被 `.gitignore` 忽略，插件配置不进版本库
- 建议通过 **Obsidian Git** 定时自动提交，或在重要改动后手动 backup

```bash
git status          # 查看改动
git add .
git commit -m "vault backup: $(date '+%Y-%m-%d %H:%M:%S')"
git push
```

## 使用建议

- **一天从一个入口开始**：先写日记，再处理 Inbox
- **每周回顾**：清空 Inbox、更新项目状态、归档已完成内容
- **少建目录，多建链接**：结构保持稳定，信息靠连接组织
- **写给自己看**：记下「为什么」比记下「是什么」更有价值

## 快速开始

1. 用 Obsidian 打开本文件夹作为 Vault
2. 在设置中确认「日记」目录为 `01-Daily（日记）`、模板目录为 `06-Templates（模板）`
3. 新建笔记时套用 `通用笔记模板`
4. 有想法先丢 `00-Inbox`，别纠结分类
